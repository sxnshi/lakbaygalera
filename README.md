# lakbaygalera
"A travel guide website for Puerto Galera, Philippines."

## GitHub Terminology for Our Project

- **"Repository (repo)":** Our shared project folder on GitHub. It holds all the files for our website.
- **"Main":** The official version of our website. Only finished, checked work goes here. This is what we submit.
- **"Branch":** Your own workspace for your assigned page (e.g. `about-page`, `contact-page`). Your changes stay there until merged into `main`.
- **"Clone":** Download our repo to your computer.
- **"Commit":** Save a checkpoint of your work with a short message (e.g. "Add about page").
- **"Push":** Upload your commits to GitHub.
- **"Pull":** Download the latest changes from GitHub. Do this before you start working each time.
- **"Fetch":** Check whether there are new changes without applying them yet.
- **"Pull request (PR)":** A request to add your branch's work to `main`. Open one when your page is done.
- **"Merge":** Combine your branch into `main` after a groupmate checks it.
- **"Merge conflict":** Two people edited the same lines of the same file. Avoid this by only editing your own files.
- **"Ahead / Behind":** Ahead means your branch has commits `main` doesn't. Behind means `main` has commits your branch doesn't. If you're behind, click **Update branch**.
- **"Collaborator":** A teammate invited to edit our repo.
- **"Initial commit":** The first commit in our repo, made when we created it.
- **"README":** The file that describes our project on the repo's front page.

## Our Team Rules

1. Never edit `main` directly. Always work on your own branch.
2. Check the branch name before every commit.
3. Only edit your own files. `style.css` is edited by one person only.
4. Open a pull request when your page is done, and a groupmate merges it.
5. Pull before you start working each time.
